## 简介
本文件面向开发者，系统化梳理 HotClaw 内置技能的实现与使用方式。重点覆盖四大核心内置技能：新闻抓取、摘要、风险检测、标题评分。文档从架构、数据流、输入输出 Schema、配置参数、执行逻辑、协作关系、性能优化、错误处理与调试方法等方面展开，并给出在 Agent 工作流中的集成要点与扩展参考。

## 项目结构
HotClaw 采用前后端分离架构，技能系统位于后端 Python 服务中，前端提供技能管理页面与技能内容查看接口。核心模块包括：
- 后端技能基类与注册中心：定义技能抽象、统一注册与检索入口
- 技能配置 API：提供技能清单查询与配置更新
- 数据模型：持久化技能元数据与配置
- 前端技能页面：展示已注册技能与配置
- 审核智能体：消费技能输出进行合规与质量评估

## 详细组件分析

### 新闻抓取技能（news_fetcher_skill）
- 角色定位：从多个新闻源抓取热点内容，为上层智能体提供外部信息输入
- 输入 Schema（示意）：关键词数组、领域、最大条目数
- 输出 Schema（示意）：文章列表，包含标题、来源、链接、发布时间、摘要
- 配置参数（示意）：新闻源列表（名称、URL、启用状态）、最大条目数、缓存 TTL、请求超时
- 执行逻辑（示意）：遍历启用的新闻源，发起 HTTP 请求并解析，去重合并，截断至最大条目数
- 性能要点：缓存命中优先、并发抓取、失败降级与重试

## 性能考虑
- 缓存策略：对热点抓取结果与重复摘要请求进行缓存，缩短响应时间
- 并发控制：限制并发抓取数量，避免上游源限流或过载
- 上下文优化：对 LLM 调用进行提示词裁剪与分段处理，降低 token 成本
- 失败降级：网络异常或上游不可用时，返回稳定占位结果或回退方案
- 日志与追踪：为关键路径添加结构化日志与 trace_id，便于性能分析与排障

## 故障排查指南
- 技能未注册：检查注册中心是否包含对应 skill_id，确认 manifest 加载与模块路径正确
- 配置更新失败：确认数据库中是否存在对应记录，检查 PUT /api/v1/skills/{skill_id}/config 的请求体
- 执行异常：捕获并记录 execute 异常，确保返回统一错误响应结构
- 前端无法加载：确认 /api/skills 与 /api/skills/content 接口可用，检查跨域与鉴权设置

## 结论
HotClaw 内置技能体系以“无状态工具”为核心理念，通过统一的基类与注册中心实现标准化接入；配合灵活的配置与持久化模型，满足不同业务场景下的内容采集、压缩、合规与质量评估需求。在 Agent 工作流中，技能以原子能力形式被调用，与审核智能体协同完成从信息获取到内容发布的闭环。

## 附录
- 使用指南
  - 在 Agent 中通过注册中心按 skill_id 获取技能实例
  - 构造符合输入 Schema 的结构化输入
