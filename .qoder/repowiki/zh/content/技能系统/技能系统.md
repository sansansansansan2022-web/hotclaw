## 引言
本文件为 HotClaw 技能系统的全面技术文档，聚焦于"技能（Skill）"与"代理（Agent）"的职责边界、技能的无状态原子能力设计、可复用性原则，以及技能基类的输入输出与配置模式。文档详细介绍了全新的技能层抽象，包括 BaseSkill 基类、标准化的 SkillResult 结构，以及首个具体实现 HotTopicFetchSkill 的完整分析。同时梳理了技能的声明式注册机制、动态加载与配置管理，并给出新增技能的开发指南、测试策略、调试方法与最佳实践，帮助开发者高效扩展与维护技能体系。

## 核心组件
- 技能基类 BaseSkill
  - 定义技能的统一接口与生命周期：技能标识、名称、描述；构造时注入配置；抽象执行接口。
  - 设计要点：无状态、原子化、稳定输出、可复用。
- 标准化技能结果 SkillResult
  - 统一的技能执行结果结构，包含状态、技能ID、数据和错误信息。
  - 提供成功和失败结果的便捷构建方法。
- 技能注册中心 SkillRegistry
  - 提供注册、查询、枚举与存在性检查；记录日志与异常抛出。
- 技能实现 HotTopicFetchSkill
  - 首个具体技能实现，负责从多个搜索引擎抓取热点数据。
  - 展示了完整的输入输出Schema定义和异步执行实现。
- 技能 API 路由
  - 列出已注册技能；更新技能配置（持久化到数据库）。
- 技能 Schema
  - 统一技能信息、列表响应与配置更新请求的数据结构。
- 代理基类 BaseAgent 与编排引擎 OrchestratorEngine
  - 代理负责业务任务与结构化输出，可调用技能；编排器按顺序调度代理节点，管理工作区与追踪。

## 架构总览

- 代理层：承担业务任务，负责输入输出与上下文传递。

## 详细组件分析

### 技能基类与职责边界
- 设计理念
  - 技能是"工具型处理"，不参与编排；应保持无状态、原子化、输出稳定且可复用。
  - 与代理的区别：代理是工作流节点，承担业务任务与结构化输出；技能仅提供可复用的工具能力。
- 接口与属性
  - 必备字段：skill_id、name、description。
  - 构造函数接收配置字典；execute 为异步执行接口，返回标准化的 SkillResult 结构。
- 可复用性原则
  - 输入输出 schema 明确；配置可注入；避免外部状态耦合；输出格式稳定。

### 标准化技能结果结构
- SkillResult 设计目标
  - 统一所有技能的执行结果格式，确保调用方能够一致地处理成功和失败场景。
  - 包含状态码、技能ID、结构化数据和错误信息。
- 核心属性
  - status：执行状态（"success" | "failed"）
  - skill_id：技能唯一标识
  - data：成功时的结构化输出数据
  - error：失败时的错误信息（包含code和message）
- 工具方法
  - to_dict()：转换为字典格式
  - is_success：判断执行是否成功
  - success()：便捷构建成功结果
  - failure()：便捷构建失败结果

### HotTopicFetchSkill：首个具体实现
- 技能概述
  - 负责从多个搜索引擎（微信搜索、搜狗搜索、360搜索）抓取热点数据。
  - 返回归一化后的原始结果列表，供代理层进行进一步处理。
- 输入输出 Schema
  - 输入：关键词列表、指定搜索引擎、每引擎最大结果数
  - 输出：归一化后的热点列表、总数量、使用的搜索引擎
- 核心功能
  - 并发抓取多个搜索引擎
  - HTML解析和数据提取
  - 结果去重和标准化
  - 异常处理和降级策略

### 代理与编排中的技能调用
- 代理职责
  - 代理负责业务任务，具备明确输入输出与上下文；可调用技能完成工具型处理。
- 编排引擎
  - 按固定顺序调度代理节点，提取输入、执行代理、回写输出至工作区；失败时尝试降级或终止。
- 技能在编排中的位置
  - 技能作为工具被代理调用，不直接参与编排节点的顺序控制。

### 四大内置技能（概念性说明）

  - 输入：标题、内容片段；输出：评分、推荐等级、改进建议。

说明：以上为概念性描述，用于指导新增技能的输入输出设计与配置项规划。具体实现需遵循技能基类接口与 Schema 规范。

## 依赖分析
- 组件内聚与耦合
  - 技能基类与注册中心低耦合：通过接口与键值访问交互。
  - API 路由依赖注册中心与数据库模型；Schema 为数据契约。
  - 代理与编排引擎通过注册中心间接依赖技能实例。
- 外部依赖与集成点
  - 前端工具通过文件系统扫描技能清单与内容，支持内置、扩展与自定义技能。
  - 技能配置持久化依赖数据库模型与路由接口。

## 性能考虑
- 技能执行
  - 保持无状态与原子化，避免长耗时阻塞；必要时引入超时与重试策略。
  - HotTopicFetchSkill 使用异步并发抓取，提高整体性能。
- 编排与工作区
  - 工作区快照与映射尽量轻量；减少不必要的数据复制。
- 日志与追踪
  - 为每个节点记录耗时与令牌统计，便于性能分析与瓶颈定位。
- 前端扫描
  - 扫描技能清单时注意 I/O 开销，建议缓存结果并在变更时刷新。

## 故障排查指南
- 技能未找到
  - 现象：查询技能时报错。
  - 排查：确认技能是否已注册；检查 skill_id 是否正确；查看注册中心日志。
- 配置更新失败
  - 现象：更新配置后未生效。
  - 排查：确认数据库记录是否存在；检查请求体结构；验证路由权限。
- 代理执行失败
  - 现象：节点失败或超时。
  - 排查：查看编排日志与错误广播；检查代理 fallback 实现；核对系统提示词来源。
- 前端技能清单为空
  - 现象：技能列表显示为空。
  - 排查：确认技能目录结构与 SKILL.md 格式；检查包路径与候选目录。
- 技能执行异常
  - 现象：技能返回失败结果。
  - 排查：检查输入参数是否符合 Schema；查看技能内部日志；验证外部服务可用性。

## 结论
HotClaw 技能系统以"无状态原子能力 + 标准化结果结构 + 声明式注册 + 结构化配置"为核心，通过代理编排与技能工具的清晰分工，实现了高内聚、可复用、易扩展的能力体系。全新的 BaseSkill 基类和标准化的 SkillResult 结构确保了技能的一致性和可靠性，而 HotTopicFetchSkill 作为首个具体实现展示了完整的技能开发模式。依托统一的 Schema、注册中心与 API 路由，开发者可以快速新增技能并纳入现有工作流；前端工具进一步增强了技能的可见性与可管理性。建议在新增技能时严格遵循输入输出与配置规范，结合测试与监控持续优化性能与稳定性。

## 附录

### 新增技能开发指南
- 接口实现
  - 继承技能基类，实现 execute 方法；设置 skill_id、name、description。
  - 定义 input_schema 和 output_schema，确保输入输出的结构化。
- 配置定义
  - 在构造函数中接收配置字典；确保配置项可序列化与持久化。
- 错误处理
  - 对异常进行捕获与包装；使用 SkillResult.failure 构建标准错误结果。
  - 必要时提供降级输出；记录日志与追踪 ID。
- 性能优化
  - 避免外部状态耦合；拆分长任务；合理使用缓存；关注 I/O 与网络延迟。
  - 考虑异步并发执行，提高吞吐量。
- 测试策略
  - 单元测试：覆盖正常路径、异常路径与边界条件。
  - 集成测试：模拟代理调用与编排执行，验证输入输出一致性。
  - 回归测试：随着配置与依赖变化，定期回归验证。
- 调试方法
  - 使用编排日志与 SSE 广播观察节点执行状态；利用前端技能清单核对技能来源与使用情况。
  - 通过 SkillResult 的 to_dict 方法输出详细的调试信息。
- 最佳实践
  - 保持技能无状态与幂等；输出结构化且稳定；为配置提供默认值与校验。
  - 为关键路径添加超时与重试；实现优雅的降级策略。
  - 遵循技能契约：不直接写主业务状态，只能被 Agent 调用。
