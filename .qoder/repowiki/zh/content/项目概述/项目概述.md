## 引言
HotClaw 是一个“基于多智能体协作的公众号内容生产平台”。其核心价值主张是：用户仅需输入“账号定位”，系统即可自动完成从热点抓取、选题策划、标题生成、正文撰写到审核风控的全链路内容生产，并输出可编辑的文章草稿。项目以 MVP（最小可行产品）为目标，聚焦“可运行、可追踪、可维护”的闭环，强调前后端分离、Agent/Skill 分层、配置优先、可视化运行与严格输入输出协议。

## 项目结构
项目采用前后端分离架构，后端基于 Python + FastAPI，前端基于 Next.js + TypeScript。整体目录组织遵循“后端目录职责边界”和“前端目录职责边界”，确保分层清晰、职责单一。

- 后端（Python + FastAPI）
  - 路由层：接收请求、参数校验、统一错误响应
  - 服务层：任务编排、配置管理、草稿与审核服务
  - 工作流引擎：加载 workflow、调度 Agent、管理 workspace、广播状态
  - Agent 层：各业务 Agent 的实现与注册
  - Skill 层：原子能力封装（如新闻抓取、摘要、风险检测、标题评分）
  - 核心工具：日志、异常、追踪、配置
  - 数据层：SQLAlchemy + Alembic + aiosqlite（MVP）

- 前端（Next.js + TypeScript）
  - 页面与路由：新建任务、任务运行、结果预览、Agent/Skill 配置、历史任务
  - 组件：可视化流水线卡片、像素风格办公场景、实时日志面板
  - 状态管理：Zustand（任务状态、配置、历史）
  - 实时通信：SSE（Server-Sent Events）

## 核心组件
- Agent（智能体）
  - 有角色、有上下文、有决策能力，负责单一业务任务，返回结构化 JSON，可调用 Skill。
  - 示例：账号定位解析、热点分析、选题策划、标题生成、正文生成、审核评估。

- Skill（技能）
  - 无状态的原子能力，封装具体技术操作（API 调用、数据处理、规则匹配），对外提供标准化输入输出。

- 工作流引擎（Orchestrator）
  - 读取 workflow 定义，按顺序/依赖调度 Agent，管理 workspace 生命周期，广播执行状态，支持降级与失败处理。

- API 网关（FastAPI）
  - 统一路由、参数校验、错误格式化、SSE 端点，保障前后端协议一致。

- 前端可视化
  - 垂直流水线卡片布局，实时展示节点状态、耗时、输出摘要；支持结果预览与导出。

## 架构总览
HotClaw 采用“前后端分离 + Agent 层 + Skill 层 + 基础设施层”的分层架构。前端通过 /api/v1 与后端交互，后端通过工作流引擎编排 Agent，Agent 调用 Skill 完成具体能力，所有节点状态通过 SSE 推送给前端，形成“可追踪、可回放、可配置”的可视化闭环。

## 详细组件分析

### 工作流引擎（OrchestratorEngine）
- 职责
  - 加载默认线性工作流（MVP 阶段为固定链路）
  - 逐节点提取输入、调用 Agent、校验输出、写入 workspace、持久化节点运行记录
  - 广播节点开始/进度/完成/错误事件，支持降级策略与失败中断
  - 记录任务耗时、累计 token 消耗，最终广播任务完成

- 关键流程（线性链路）
  - 账号定位解析 → 热点分析 → 选题策划 → 标题生成 → 正文生成 → 审核评估

## 性能考量
- 线程与异步
  - 后端使用 asyncio 与 FastAPI 异步支持，SSE 推送与数据库异步 IO，降低阻塞
- 超时与降级
  - 工作流引擎为每个节点设置超时，失败时执行 Agent 降级策略，避免整条链路崩溃
- 缓存与持久化
  - Redis 用于缓存热点与配置，SQLite 存储任务与节点运行记录，减少重复计算
- 可观测性
  - trace_id 传播、结构化日志、节点耗时与 token 统计，便于性能分析与问题定位

## 故障排查指南
- 常见问题与定位
  - 节点失败：查看节点运行记录（输入/输出/错误信息），确认是否触发降级
  - 任务级错误：检查任务状态与错误消息，定位首个失败节点
  - SSE 连接异常：确认 /api/v1/tasks/{id}/stream 是否可达，浏览器控制台网络面板
  - Agent/Skill 配置异常：检查配置项 schema 与默认值，必要时回滚至默认配置
- 前端状态处理
  - 正确处理 loading/error/empty/success 四态，避免静默失败
- 后端异常处理
  - 统一异常映射为 HTTP 状态码，错误响应包含 code/message/details

## 结论
HotClaw 以“可运行、可追踪、可维护”为核心目标，通过前后端分离、Agent/Skill 分层与可视化运行，构建了从账号定位到文章草稿输出的最小闭环。MVP 阶段聚焦线性工作流与基础能力，后续可在保持协议稳定的前提下逐步扩展为 DAG 工作流、插件系统与多账号管理。
