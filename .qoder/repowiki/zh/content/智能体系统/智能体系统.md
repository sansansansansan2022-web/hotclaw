## 简介
本技术文档面向HotClaw智能体系统，系统采用“工作流编排 + 多智能体节点”的架构，围绕六大核心Agent构建从账号定位到内容发布的完整链路。文档涵盖：
- Agent体系的整体架构与基类设计、继承关系与核心接口
- 六大核心Agent的职责、输入输出Schema、依赖的Skill、降级策略与执行逻辑
- Agent注册机制、动态加载与配置管理
- Agent间协作模式、数据流转与错误处理策略
- 新增Agent的开发指南与最佳实践

## 架构总览
系统以“任务”为单位，编排引擎按顺序驱动各Agent节点执行，节点间通过工作空间共享上下文；每个节点执行前会解析有效系统提示（优先DB自定义），执行后写入节点运行记录并广播状态。

```mermaid
sequenceDiagram
participant Client as "客户端"
participant API as "Agent配置API"
participant Engine as "编排引擎"
participant Reg as "Agent注册中心"
participant Agent as "具体Agent"
participant DB as "数据库"
participant WS as "工作空间"
Client->>API : 获取Agent清单/详情
API-->>Client : 返回Agent信息
Client->>Engine : 提交任务(含positioning)
Engine->>WS : 初始化工作空间
loop 依次执行节点
Engine->>Reg : 获取agent_id对应的Agent实例
Reg-->>Engine : 返回Agent实例
Engine->>DB : 解析有效系统提示(自定义/默认)
Engine->>WS : 提取输入映射
Engine->>Agent : 执行execute(input_data, context)
Agent-->>Engine : AgentResult(成功/失败)
alt 成功
Engine->>WS : 写入输出键值
Engine->>DB : 记录节点完成
else 失败
Engine->>Agent : 触发fallback(error, input_data)
alt 降级成功
Engine->>WS : 写入降级输出
Engine->>DB : 记录降级标记
else 必需节点
Engine->>DB : 记录节点失败
Engine-->>Client : 抛出执行错误
end
end
end
Engine->>DB : 任务完成，汇总统计
Engine-->>Client : 返回最终结果
```

## 详细组件分析

### BaseAgent与AgentResult
- 设计要点
  - 统一接口：execute(input_data: dict, context: dict) -> AgentResult
  - 结果封装：AgentResult包含状态、名称、数据、错误与追踪ID
  - 降级策略：fallback(error, input_data) -> 可选降级结果
  - 工具方法：_success/_failure快速构造标准结果
  - 系统提示：支持从上下文覆盖默认系统提示

### 编排引擎与工作空间
- 默认线性工作流节点（MVP）
  - profile_parsing -> hot_topic_analysis -> topic_planning -> title_generation -> content_writing -> audit
- 执行流程
  - 初始化工作空间与任务状态
  - 逐节点提取输入映射、解析有效系统提示、执行Agent、写回输出
  - 失败时尝试fallback，必需节点失败则终止并抛错
  - 广播节点开始/完成事件，记录节点运行指标
  - 任务完成后汇总统计并关闭

```mermaid
flowchart TD
S(["开始任务"]) --> Init["初始化工作空间/任务状态"]
Init --> Loop{"遍历节点"}
Loop --> |提取输入| Exec["执行Agent.execute(...)"]
Exec --> Ok{"成功?"}
Ok --> |是| Save["写入输出到工作空间"]
Save --> Next["下一个节点"]
Ok --> |否| FB["调用Agent.fallback(...)"]
FB --> FBok{"降级成功?"}
FBok --> |是| SaveDeg["写入降级输出并标记degraded"]
FBok --> |否| Req{"必需节点?"}
Req --> |是| Fail["记录节点失败并抛错"]
Req --> |否| Skip["记录失败但跳过"]
SaveDeg --> Next
Skip --> Next
Next --> Loop
Loop --> |完成| Done["任务完成，汇总统计，广播完成"]
```

## 依赖分析
- 组件耦合
  - 编排引擎强依赖注册中心与工作空间，弱依赖数据库与广播器
  - Agent仅依赖注册中心与上下文，不直接访问数据库
  - API层依赖注册中心与数据库，用于查询与更新Agent配置
- 外部依赖
  - LLM：通过系统提示与模型配置控制
  - Redis：用于广播与缓存（由配置项体现）
  - 数据库：SQLAlchemy异步ORM
